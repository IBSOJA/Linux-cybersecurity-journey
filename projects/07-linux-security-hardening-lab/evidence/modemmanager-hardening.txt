Project 07 — Linux Security Hardening Lab
Evidence: ModemManager Hardening
Date: 2026-09-28
Host: Ubuntu 24.04.x LTS
User: vboxuser

1. Objective
-------------
Investigate ModemManager to determine whether it is required in the
current Ubuntu VirtualBox environment, assess its dependencies and
exposure, temporarily stop it to test system functionality, and
permanently disable it if safe to do so.

2. Baseline
-----------
Initial service status:

ModemManager.service was active/running and enabled.

Main process:

/usr/sbin/ModemManager

The service was running as root and contained several systemd security
restrictions including:

ProtectSystem=true
ProtectHome=true
PrivateTmp=true
NoNewPrivileges=true

The service was configured to start through:

WantedBy=multi-user.target

It also required polkit.service.

3. Modem Hardware Investigation
-------------------------------
Checked for detected modems with:

mmcli -L

Result:

No modems were found

This indicated that no modem device was currently being managed by
ModemManager.

4. Dependency Investigation
---------------------------
Checked reverse dependencies with:

systemctl list-dependencies --reverse ModemManager.service

Result:

ModemManager.service
└─multi-user.target
  └─graphical.target

No specific application or system service was identified as requiring
ModemManager.

The service was started as part of the normal multi-user boot target.

5. Network Exposure Investigation
---------------------------------

sudo ss -lntup | grep -i modem

No output.

No network listener associated with ModemManager was identified.

----------------------

ModemManager was permanently disabled with:

/etc/systemd/system/dbus-org.freedesktop.ModemManager1.service

11. Security Assessment
-----------------------
ModemManager was running with root privileges but no modem hardware
was detected in the current VirtualBox environment.

No specific service dependency was identified, and no network listener
associated with ModemManager was observed.

The service was temporarily stopped and the system continued to
function normally. NetworkManager, DNS resolution, the graphical
environment, SSH, and Internet connectivity remained operational.

For this specific lab environment, ModemManager was therefore
permanently disabled as part of service minimization and attack-surface
reduction.

This decision is environment-specific. If cellular/mobile-broadband
hardware is later added or required, ModemManager may need to be
re-enabled.
